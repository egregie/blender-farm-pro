# ТЗ — пропорции картонки по арт-дирекции референсов

**Дата:** 2026-08-07 · **Статус:** утверждено, к исполнению
**Решает:** пункт 1 `00_PROJECT_STATE/NEXT_STEPS.md` (блокирующее решение), разблокирует пункт 2.

## Goal

Перевести геометрию картонки на пропорции, заданные референсными рендерами, сохранив при
этом настоящие паспортные размеры как единственное, что печатается на упаковке.

## Project Boundary

`C:\lil_projects\Blender Farm Pro`. Читать и изменять что-либо за пределами запрещено.

## Context

Решение принято владельцем проекта: пропорции определяет арт-дирекция референсов, а не
строка `secondary_packaging.dimensions`.

Утверждённый подход: переформовка на границе манифеста (`src/render_manifest.py`), контракт
1.2 → 1.3 несёт **оба** набора чисел — арт-геометрию для сцены и паспортные размеры для
печати. Якорь: сохраняются наибольшее паспортное измерение и глубина, оставшееся решается
под целевую пропорцию силуэта. Кадрирование не трогается.

**Достоверность исходных замеров под вопросом.** Таблица «Measured silhouette fill» в
`CURRENT_STATE.md` систематически занижает высоту силуэта у ландшафтных коробок. Проверено:
аналитическая проекция восьми углов воспроизводит углы, которые Blender записал в
`tests/fixtures/ocr/1-min.view.json`, с погрешностью 0.0 px, и для `115x55x48` даёт 76/57
против 74/48 в таблице. Вероятная причина — измерение силуэта по пикселям при белой
картонке на фоне 255: ярко освещённая верхняя грань сливается с фоном, а у ландшафтных
коробок она составляет заметную долю силуэта. Строить целевые пропорции на этих числах
нельзя, пока метод измерения не откалиброван.

## Scope

**Included:** аналитическая модель силуэта как модуль проекта; калибровка измерения по
изображению против неё; замер девяти референсов и фиксация целевых пропорций константами;
переформовка в `src/render_manifest.py`; контракт 1.3 и перегенерация манифестов; печать
паспортных размеров на боковой панели; тесты; перезапуск 391-SKU свипа; перегенерация
фикстуры OCR-барьера.

**Excluded:** кадрирование (`SPHERE_FILL`, `LENS_MM`, `SENSOR_MM`, `PITCH_DEG`,
`ROTATION_DEG`); световой риг; константы сетки подписей (только перепроверка поведения);
`T2` — ноль SKU; пункты 3–8 `NEXT_STEPS.md`.

## Functional Requirements

1. Геометрия каждого SKU попадает в целевую пропорцию своего шаблона.
2. Манифест несёт неизменённые паспортные размеры отдельным обязательным полем.
3. Боковая панель печатает паспортные размеры. Геометрические на упаковку не попадают.
4. `carton.source` различает происхождение геометрии, включая арт-дирекцию.
5. Целевые пропорции — замеренные константы, не расчёт по изображениям во время работы.
6. Манифест версии 1.2 отвергается валидацией.

## Architecture Requirements

**Владение.** Переформовка целиком принадлежит `src/render_manifest.py`. Драйвер не получает
ни таблицы пропорций, ни знания о переформовке. Копия таблицы пропорций в драйвере однажды
существовала и была удалена как дублирующий источник правды — воспроизводить запрещено.

**Изоляция Blender.** Драйвер исполняется внутри интерпретатора Blender, где модули проекта
недоступны. Аналитическая модель живёт в `src/` и в драйвер не попадает.

**Порядок операций.** `orient_for_template()` применяется до переформовки.

**Модель силуэта.** Проецируются все восемь углов; силуэт — габаритный прямоугольник
проекций. Параметры камеры дублировать запрещено: если импорт невозможен, значения читаются
из одного места и тест сверяет их с драйвером.

**Калибровка.** Метод измерения по изображению годен только после того, как на наших
рендерах воспроизводит аналитическую модель. Порог согласия задаёт и обосновывает
исполнитель. Референсы измеряются только откалиброванным методом.

## Invariants

Нарушение любого — остановка и вопрос, не обход.

1. **На упаковке печатаются только паспортные размеры.** Проект уже отказался печатать
   правдоподобные LOT/EXP как выдумывание данных на фармацевтической упаковке. Печать
   переформованных размеров — то же самое, только числами.
2. **Манифест — единственное описание того, что получает Stage 2.**
3. **`import bpy` только в `05_assets/blender/render_driver.py`.**
4. **Жёсткий сбой в драйвере — только `SystemExit`.** Обычное исключение оставляет код 0,
   и Stage 2 засчитает провал как успех.
5. **Кадрирование общее для всех 391 SKU.**
6. **Ни один SKU не теряет провенанс.**
7. **Все 391 манифеста валидны по 1.3.** Частичная миграция недопустима.
8. **Тесты — stdlib `unittest`, не pytest.**

## Implementation Steps

Каждый шаг — одно проверяемое изменение, коммит после каждого, тесты до реализации.

1. **Discovery.** Выполнить Discovery Phase, записать исходные показатели.
2. **Аналитическая модель силуэта.** Модуль в `src/`. Тест: воспроизводит четыре угла
   лицевой грани из `tests/fixtures/ocr/1-min.view.json` не хуже 0.1 px. Не проходит —
   остановиться, это фундамент всего остального.
3. **Проверка на втором шаблоне.** `--dump-scene` для SKU вертикального семейства, сверка
   так же. Одна совпавшая точка модель не доказывает.
4. **Калибровка измерения по изображению.** Применить существующий код к нашим рендерам,
   сравнить с моделью. Систематическое расхождение — найти причину, не подгонять порог.
   Результат с числами в отчёт.
5. **Замер референсов.** Откалиброванным методом измерить девять изображений. Записать
   целевые пропорции константами с датой, методом и исходными числами.
6. **Функция переформовки.** В `src/render_manifest.py`. Тесты: попадание в целевую
   пропорцию по модели из шага 2 для каждой реальной тройки размеров каталога.
7. **Контракт 1.3.** Новое **обязательное** поле с паспортными размерами, новое значение
   `carton.source`, `const` до `1.3`. Тест: манифест 1.2 отвергается.
8. **Сборка манифеста.** Подключить переформовку, перегенерировать все манифесты. Тест по
   каталогу: 391 валиден, паспортные размеры совпадают с паспортом побайтово, геометрия
   попадает в целевую пропорцию.
9. **Боковая панель.** Переключить блок данных на паспортное поле. Тест: построенная строка
   сверяется с манифестом побайтово, как уже сделано для строк подписи.
10. **Проверка силуэта в сцене.** Тест через `--dump-scene` на трёх семействах минимум,
    включая T3 и вертикальное.
11. **Побочные эффекты.** Перезапустить свип `top30`; перепроверить сетку подписей,
    распределение портрет/ландшафт для экспозиции, предупреждения о ширине модуля
    штрихкода. Каждое расхождение — находка в отчёт, не тихая правка.
12. **Фикстура OCR-барьера.** Перегенерировать `tests/fixtures/ocr/1-min.*`, убедиться, что
    барьер держится.
13. **Документы.** Обновить `CURRENT_STATE.md` (заменить недостоверную таблицу замеров),
    убрать пункт 1 из `NEXT_STEPS.md` и перенумеровать, дописать в `CLAUDE.md`, что
    геометрия и печатаемые размеры — разные вещи и почему.

## Edge Cases

1. **Переворот ориентации.** `T1` `55x100x55` и `45x80x45` (по 1 SKU) под переформовкой
   становятся ландшафтными из портретных — это настоящие вертикальные коробки в
   горизонтальном шаблоне. Молча переворачивать нельзя: остановиться и спросить.
2. **Решённое измерение вне допустимого** (ноль, отрицательное, больше якоря) — зафиксировать,
   остановиться, спросить. Не подправлять формулу.
3. **Шаблон с несколькими тройками размеров** (`T1` — пять, `T3` — две, `T_BOTTLE_BOX` — три):
   одна целевая пропорция, разные абсолютные размеры. Ожидаемо.
4. **Шаблон, уже совпадающий с референсом** (`T_MULTIPACK`, `T_BOTTLE_BOX`, 4–6%): правило
   применяется одинаково, исключений в коде быть не должно.
5. **Референс не измеряется** — находка, не повод взять число из старой таблицы.
6. **Калибровка не сходится** — остановиться: дефект в одной из двух сторон, найти до
   продолжения.
